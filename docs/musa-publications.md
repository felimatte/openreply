# Publishing from MUSA

MUSA calls `PUT /api/integrations/musa/v1/publications/{uuid}` only when an approved piece is due. Authenticate with the paired MUSA token and business header. Each call performs at most one provider operation (3.5-second network timeout) and returns the durable receipt. Repeat the same PUT after `retryAfterSeconds` while `status` is `processing`. GET may recover an existing receipt using read-only provider calls; it never creates a container or publishes.

The UUID is globally unique and permanently records its payload hash. Changing the account, caption, media URL, cover or campaign under an existing UUID returns 409. Reconnecting MUSA cannot make the same UUID publish again. Processing has a persistent 30-second lease; the application does not rely on in-memory locks or a request staying alive while Instagram transcodes a video.

## Compatible payloads

The original strict request `{accountId,caption,videoUrl,coverUrl?,campaignId?}` remains a Reel, with URLs up to 4096 characters and exactly its original hash. Existing ledger payloads are not rewritten or rehashed.

The modern strict request is `{accountId,caption,format,mediaItems:[{type,url}],campaignId?}`. `format` is `reel`, `image` or `carousel`; `type` is `image` or `video`. A Reel has exactly one video, an image exactly one image, and a carousel 2–10 ordered images/videos, including mixed media. Modern URLs are bounded to 2000 characters; captions to 2200. Unknown keys and mixing old/new fields are rejected. Body size is bounded to 40,000 UTF-8 bytes. Format, media types and order participate in a versioned hash; reordering under an existing UUID returns 409.

`GET /accounts` advertises `supportedFormats: ["reel","image","carousel"]` only when `canPublish` is true, otherwise `[]`. An older response without this property means Reel-only. The existing publication permission covers all three formats; no messaging engine or new OAuth scope is enabled by this change. The execution preflight revalidates current authorization and the selected format.

## Providers

- Meta: the account must have granted `instagram_business_basic` and `instagram_business_content_publish`. Standard Instagram connection/reconnection keeps the existing automation scopes; it does not request publishing. Workspace owners/admins explicitly choose **Allow video publishing** for a Meta account in the MUSA settings, using `purpose=publish` with the workspace and local account ID. The signed OAuth state binds that account, and the callback rejects a different Instagram identity. Enable the permission in the Meta app before this opt-in; external customer accounts require the applicable Advanced Access/App Review. Returning from OAuth does not prove the scope was granted: the capability check makes a read-only GET to that account's `content_publishing_limit`, which requires both permissions with Instagram Login, and validates the quota response. An exhausted quota still confirms authorization; the publication pipeline checks capacity separately. Errors and invalid responses keep publishing unavailable. The steps are create container, poll readiness, read actual account quota, publish, then record the confirmed media ID. Containers are created when due, not when planning the calendar.
- Zernio: the account health response must confirm `permissions.canPost` and a valid token. A post is scheduled about 30 seconds after dispatch so Zernio handles the video asynchronously. `publishNow` is synchronous and is deliberately not used. The same UUID and original timestamp are reused with `Idempotency-Key` after uncertain creation, only within 23 hours of the first attempt (the documented window is 24 hours). Thereafter the receipt becomes uncertain.

All media and the legacy optional cover must be direct public HTTPS URLs, downloadable by the provider. MUSA/OpenReply do not download or inspect caller-controlled URLs, generate media, or copy files from a sharing webpage. The files must satisfy the selected provider's format, duration and size restrictions. For portable photos use JPEG sRGB, up to 8 MB and aspect ratio 4:5–1.91:1; carousel slides share the first slide's aspect ratio. Zernio documents additional accepted image formats. Video slides are plain video containers, not Reels; do not apply Story-only duration limits. No actual publication is performed by the test suite.

Meta images create a container with `image_url` and then reuse readiness/quota/publish/receipt steps. A carousel creates each child with `is_carousel_item=true`; video children also set `media_type=VIDEO`. The ordered `childContainerIds` array persists progress before another step runs. Each child must reach `FINISHED` before the next child, then a parent with `media_type=CAROUSEL` is created from the ordered IDs. Only the parent enters the publish/confirmation path. `PUBLISHED` on a child never proves publication of the carousel. A write-ahead child-creation marker that loses its response becomes uncertain rather than repeating the POST. Definite rate limits preserve the current step; the same parent is never replaced by recreating children. Containers are created when due, expire after 24 hours and have a separate creation quota.

Zernio receives the same ordered `mediaItems`, preserving image/video types. It retains the asynchronous schedule, stable UUID and original timestamp for idempotent retries. A single video becomes a Reel; multiple items become a carousel.

## Confirmation and campaigns

`published` requires a confirmed Instagram media ID or the existing exact Meta container proof: `confirmation: {source:"meta_container",containerId,status:"PUBLISHED"}` when no media ID/permalink is available. For a carousel this ID is exclusively its parent; the database rejects a saved child as the parent. An interrupted or timed-out Meta publish operation becomes `uncertain`; repeated PUTs return that state without repeating the publish call. Never turn an uncertain result into an automatic retry under a new UUID.

An optional campaign must be paused, belong to this workspace/account, have no assigned post, and not target every post or DMs. A paused “next Reel” draft can be selected. Its target and activation are locked by a database trigger while publication is processing or uncertain, preventing the next-Reel worker from winning a race. After confirmation the exact media ID is assigned, next-Reel flags are cleared, and the campaign stays paused. Campaign activation remains a separate human action.

If the campaign changed or disappeared, a confirmed video remains `published` with `CAMPAIGN_BINDING_CONFLICT`. This reports the failed association without resending the already published video. Permalink lookup failure likewise does not invalidate a confirmed media ID.

A definite failure releases the campaign reservation (the requested campaign remains in the immutable payload). An uncertain result keeps the reservation. Losing access to an already submitted Zernio post is uncertain, since revoking a credential does not cancel the remote post.

Apply all MUSA migrations, including `20261025120000_musa_multiformat`, before serving this version. The migration only adds ordered child progress and constraints; old rows get an empty list and keep their original payload/hash. The ledger is retained when grants are revoked. The API rechecks the grant, granting administrator and account scope on every call. Publish the compatible OpenReply server before enabling new formats in MUSA. Once a carousel has started, do not roll OpenReply back to a Reel-only implementation; keep the additive schema and compatible processor until active publications have resolved.

## Verification

`npm test` covers the state machine and provider boundaries using mocked HTTP. To exercise real PostgreSQL leases, unique reservations and campaign guards, point `MUSA_TEST_DATABASE_URL` at the dedicated local database `postgresql://postgres:postgres@127.0.0.1:57322/openreply_musa_qa`, apply migrations, and run `npx vitest run __tests__/musa-publications.db.test.ts`. The test rejects any other host, port or database, creates its own fixtures, forbids external fetches, and removes only those fixtures.

For an optional socket-free DDL check when `@electric-sql/pglite` is already available in the QA tooling, run `node scripts/qa-musa-multiformat-pglite.mjs`. It applies the repository's migration SQL unchanged to in-memory PostgreSQL WASM, inserts a legacy receipt before the additive migration, and checks ordered progress, parent/child constraints, exact proof, campaign guards and lease CAS predicates. It writes a synthetic report under `progress/`. This is a direct-SQL check, not Prisma transport or concurrency between independent database sessions; the PostgreSQL CI suites remain separate. The script does not install dependencies, read service configuration, expose a socket or contact a provider.
